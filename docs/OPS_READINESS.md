## 2026-09-19 首轮措施（后续增量见文末）

- 产量服务拒绝直接发运，发运统一经已占用装箱方案；方案ID作为业务幂等身份。数量、状态和审计在同一事务提交。
- 投产阻塞在服务端检查。产量幂等键绑定类型、数量及色尺内容；同键不同内容拒绝。
- 占库不超过本单需求。预览指纹绑定需求、报价、供给，采用时在事务内重新校验；单位、币种、未确认单耗或采购规则不支持时不可采用。
- 采购供给与报价批量查询，BOM从1种到21种材料的真实SQL查询数相同。工厂进度台在数据库查询条件内限制工厂。
- AI输入最多50,000个UTF-16字符、模型HTTP响应最多1 MiB、超时20秒。模型请求附输出结构；字段来源、定位和数量依据需核对原文。错误不回显模型原始响应。
- 重新解析使旧预览过期；生产环境拒绝演示密码登录，会话读取复核用户当前有效状态和角色。
- 测试库使用固定的绝对路径，拒绝符号链接；不继承演示数据库URL。初始化不再使用SQLite不支持的skipDuplicates。
- 源文件回写前核验基线哈希，保留旧文件；不执行数据库schema变更、演示库迁移、重建或历史记录更正。

## 本地数据库路径

Prisma schema位于prisma/schema.prisma，因此当前file:./prisma/dev.db实际解析到项目内prisma/prisma/dev.db。外层prisma/dev.db可能是空文件，不能凭文件名选择备份对象。

上线应配置明确的数据库绝对路径和独立私有附件目录，并在进程启动时核对实际路径。测试、演示、生产必须分别管理，禁止将测试reset/seed脚本接到生产启动命令。

## 性能：上线前必须验证

本轮SQL查询数量检查仅证明采购比较没有逐BOM行增加查询，不证明生产容量。

需用预期的订单、材料、来源及附件规模测试：首页、进度台、检索、采购比较、录入与发运的p50/p95、错误率、进程内存和数据库锁等待。列表需要数据库分页与索引验收，不能依赖全量加载后的内存筛选。API输入/附件数量限制与大文件并发也需验证。

当前SQLite单写入边界和订单写事务已用于本地回归。不得据此宣称多进程/多实例可承载真实并发；PostgreSQL迁移涉及类型、事务隔离、约束、索引、连接池、迁移和并发重测。

## 安全：仍未完成的上线条件

- 正式用户认证、会话撤销策略、密钥轮换与最小权限角色清单；演示登录在production被禁止，因此当前不能直接当正式登录部署。
- 全路由组织/工厂/字段级权限审计，包括来源正文、附件下载、历史复用、工厂改派、报价与审计记录。
- 登录和昂贵接口限流、请求体/附件解压上限、CSRF及跨域策略、安全响应头、反向代理限制、TLS与依赖漏洞检查。
- 真实模型供应商的数据处理授权、接口能力、调用预算、脱敏和异常恢复；本轮未调用付费模型。
- 结构与来源校验不等于模型理解始终正确，含糊内容仍需人核对。当前数值证据支持原文阿拉伯数字，中文数词/特殊缩写不能凭模型猜成可执行数量。

## 数据：业务边界仍需补齐

- 生产批次、多款订单的款式归属、逐色尺合格库存、返工/WIP流转与受控冲销更正。本轮遇到多款装箱会拒绝合并，不生成缺少款式依据的装箱记录。
- 旧记录仅有整单合格数量时，本轮校验色尺存在与整单可发上限，不能宣称已做到每个色尺的成品余额校验。
- 采购的颜色/尺码适用单耗、批次色号可用性、精度/舍入口径、调拨时效、采购后续修改影响需进一步验收；当前正式采购/付款保持关闭。
- AIJob进程崩溃后的租约与有限重试、并发重解析、批准时依据的事务一致性、跨来源冲突处理尚需独立工作。
- 既有采购草稿在订单/BOM/报价变更后的持续失效机制需补齐。本轮保护的是预览至采用这一步，ETA已有过期机制继续保留。
- 原演示库可能有既存不一致。本轮不自动修正，不把历史零数量当成已核实的未投产。

## 备份、恢复与发布

1. 发布前记录代码版本、迁移版本、运行配置名称、实际数据库路径、私有附件根目录与校验清单；禁止将密钥写入报告。
2. SQLite运行时使用Online Backup API获得一致快照，不能只复制活动db文件而忽略WAL。数据库、私有附件和两者的引用关系都需备份，备份文件限制权限并按组织要求加密存放。
3. 先恢复到独立目录与独立进程，运行PRAGMA quick_check和PRAGMA foreign_key_check，再核对关键业务数量与抽样附件。恢复不得覆盖正在使用的库。
4. 由负责人确定可接受的数据丢失时间与恢复时间；安排备份保留、异地副本、恢复演练和责任人。
5. 部署先验证回退路径；需要迁移时明确新旧程序兼容性。代码回退不能冒充数据回退。
6. 监控错误率/延迟、磁盘、数据库锁、积压或卡住的AIJob、备份时间与恢复演练结果。独立worker当前未实现持续处理，不能对外声称后台一直在监控。

本轮仅在独立虚构SQLite副本演练Online Backup，验证42张表逻辑数据一致、quick_check=ok、外键错误0。未演练真实生产恢复或私有附件恢复。
