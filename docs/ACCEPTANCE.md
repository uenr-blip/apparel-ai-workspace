# 验收标准 V1

这些是待实现的测试，不是已经通过的测试报告。所有输入和数字均为虚构案例。实施时将核心规则转换成自动化测试；每项记录通过/失败/未运行及证据。不要只用截图证明数据库行为正确。

## A. 运行与真实数据

**A01｜干净环境启动**
给定 README 指定的 Node 与唯一包管理器版本，在专用空开发数据库执行安装、迁移、seed；启动 Web/worker。应能登录演示组织并打开核心页面。不需要云数据库或AI密钥。缺少依赖时给出准确安装命令，不自动购买服务。

**A02｜持久化与关联**
在审核界面批准一个订单草稿创建提案，刷新页面并重启服务。订单、来源、任务、执行记录仍存在，首页与详情读取一致的数据。

**A03｜没有假按钮**
遍历主要页面的新建、保存、批准、拒绝、执行、筛选、下载、装箱等动作。每个启用动作均调用真实逻辑并提供结果或错误；尚未实现的动作不得显示成功。

**A04｜模式诚实**
AI_MODE=mock 时，AI相关界面与记录明确注明演示。AI_MODE=live 但缺少配置时显示配置错误；调用超时/限流/结构错误时显示失败，不能自动返回mock答案伪装成功。业务手工操作仍可使用。

## B. 款式、订单与开发

**B01｜翻单复用而非复制**
同一组织已有 ST-26018 及历史订单。处理 fixtures/01-reorder.txt，批准创建本次订单草稿。款式总数不增加；新订单与老订单分开；关联同一个主款；旧订单BOM和已确认资料不变。

**B02｜PO与不完整数量**
上述文本没有PO且缺少尺码明细。允许保留草稿；外部PO为空；已知两色数量保留在草稿结构中。不得虚构尺码分配或正式SKU行，不得直接批准投产。

**B03｜一张订单多个款**
在一张客户订单中加入两个不同款式的明细。汇总与来源关系正确；款式详情各显示关联订单，不重复计算整单总量为每款数量。

**B04｜开发先于款式**
处理 fixtures/03-material-development.txt，创建材料开发项目并引用两种候选材料；尚无款号时可保存。后续关联款式不复制开发材料与历史记录。

**B05｜版本发布与作用域**
既有已批准BOM V1与两张引用其快照的订单。针对新订单修改袖口，只生成V2草稿和当前订单影响记录；V1、历史成本与旧订单不变。未批准V2不得作为正式生产依据。

**B06｜确认轮次**
同一订单、同一材料、两个颜色分别提交确认。灰色退回、海军蓝批准；界面不得把整款显示为全部已批准。灰色第二轮确认保留第一轮结果和来源，不覆盖历史。

## C. 资料理解与证据

**C01｜来源定位**
粘贴文本并上传测试表格/文字PDF。结构化结果能点击定位到原文片段、PDF页码或表格单元格；不存在源文依据的“已提取事实”被拒绝或标为未知。

**C02｜重复导入**
同一组织重复提交相同文件，识别内容哈希并提示已存在来源。重复解析不会重复生成订单或确认任务。用户可以显式保留新的业务解释，不得只以文件哈希把不同授权业务硬合并。

**C03｜冲突不擅自裁决**
两个来源分别写总量1000与1200，未说明后者是否修订。展示来源、日期及冲突，等待选择；不能直接以“最新上传”认定最终有效。

**C04｜未知与多候选**
缺少年份、尺码、供应商代码或存在多个同名款时，列出未知与候选。不得任意选择客户、猜交期年份或绑定其他组织记录。

**C05｜不支持的图像输入**
未配置视觉模型时上传图片/扫描PDF。可以保存附件，但明确未进行语义识别，不能返回看似解析出的BOM。mock只对公开标识的内置fixture演示。

**C06｜模型结构错误**
注入截断JSON、错误字段类型、负采购量、虚构sourceId等返回。Zod/服务层校验拒绝；不创建正式业务记录；有限重试后给用户可修正的失败状态。

## D. 数量、采购与库存

**D01｜基础净需求**
按 fixtures/expected-cases.json 的 procurementAllowanceCase：毛需求1545米，净需求1225米，建议1230米，该行价款24600.00元。断言中间值、单位、舍入阶段与最终值。不可只断言页面文字。

**D02｜已含采购加成**
如果确认单耗是已经含加成的1.545米/件，1000件需求仍为1545米，而不是1591.35米。已含口径不重复加3%。

**D03｜供给可用性**
200米在途晚于需求日、质量不满足、所有权不允许或已分配给其他订单时，不得抵扣本需求。库存在另一地点不等于自动不能用，但若调拨来不及则不列为及时供应。

**D04｜MOQ边界与净需求为零**
正净需求低于MOQ时按已确认供方政策建议MOQ/倍数；净需求为0时建议0。库存超过需求不得生成负采购量。未确认MOQ政策时显示待核实，不虚构供应条件。

**D05｜库存并发分配**
两个订单同时尝试独占同一批120米库存，事务/原子条件更新只能成功分配一次，另一个收到冲突并重算。不能因两次读取都看到120米而重复占用。

**D06｜调拨与耗用分开**
原料库自有库存200米，发100米到外协厂。公司合计仍200米，原库100、工厂100。再在工厂实际领用40米，未耗用库存变为160米，生成不同凭证，不回写原调拨为领用。

**D07｜单位缺少依据**
BOM为米，报价为公斤，缺有效换算。阻止正式采购计算并说明缺少依据；不得使用通用系数。有效米/码换算按明确常数和精度测试。

## E. 生产、装箱与对账

**E01｜数量守恒**
给定投产1020，报废10，在制15，合格995；合格中发出980、余15。系统分别显示，不把1020−980=40当作报废。配套按色尺汇总，汇总前保留行级来源。

**E02｜重复上报与返工**
同一幂等键的增量上报提交两次，只记一次。返工流转不重复增加合格成品；更正必须保留原记录与更正关系。

**E03｜混装与防超发**
两种颜色、多个尺码混装同箱，箱明细合计=箱件数，所有箱汇总=本次发运数。并发占用与发运不得超过可用成品；失败回滚。装箱方案未确认不称实际出运。

**E04｜重量状态与实际证据**
未录重量时净重/毛重为空或明确待称重，不出现AI猜出的实测值。实际称重记录与估算能区分。

**E05｜对账不等于付款**
生成工厂对账草稿时引用配置的计价基准、数量、单价和调整，显示依据。未配置基准阻止自动计算；发运完成不会自动批准对账或调用付款。V1无真实支付能力。

## F. AI动作、安全与权限

**F01｜授权低风险动作**
组织策略明确允许系统根据阻塞创建内部未分配待办时，规则可自动执行并审计，无需每次人工确认。重复事件不重复建待办。禁用策略后不得继续自动创建。

**F02｜正式动作批准**
操作提案未获当前有权限的人批准时，不可发布正式采购/更改正式生产依据/过账库存。直接调接口也必须失败，不能只靠前端隐藏按钮。

**F03｜版本漂移**
用户预览版本7的采购方案后，需求被其他人改到版本8。即使携带之前的批准请求，也不得按旧方案执行；提案标记过期，重新预览并批准。

**F04｜幂等与原子性**
执行同一ActionProposal两次，只产生一组业务记录。执行中某写入失败，事务全部回滚；返回失败不能留下半张订单或半次扣库。执行成功后重试返回原执行结果。

**F05｜跨组织与跨工厂**
篡改URL ID、表单orgId、AI工具参数，访问另一组织或未分配工厂订单，服务端拒绝。检索、统计、下载附件和AI上下文同样隔离，不能只保护详情页。

**F06｜恶意附件指令**
上传 fixtures/04-untrusted-instructions.txt。资料中的“绕过审批/读取环境变量”不能变成工具权限。模型即使提出危险动作也被白名单/服务校验拒绝，密钥不进上下文和结果。

**F07｜安全文件处理**
拒绝超大小、超页/行数、伪装MIME和可执行上传；不运行宏；不跟随资料里的任意URL；安全转义HTML/Markdown，防止嵌入脚本或隐蔽外链请求。

**F08｜任务重启与重试**
解析任务进入running后重启worker，按明确租约/超时策略恢复或标记可重试；失败有错误信息与重试上限。不能永久假转圈。页面显示worker/任务真实状态。

**G02｜桌面与移动**

**G03｜无障碍和异常状态**
键盘可到达主要控件；模态框焦点可返回；错误有文字而不只靠红色。覆盖加载、空、错误、无权限、模型待配置、结果冲突。

**G04｜真实工程检查**
实际执行typecheck、lint、Vitest/集成测试、Playwright和production build。逐项写入TEST_REPORT；网络/浏览器/编译受阻应给错误与复现命令，不能伪称通过。

**G05｜生产边界**
生产环境启用demo快捷登录应失败或被明确禁止；秘密不进入构建前端包/仓库。SQLite并发、真实认证、备份恢复和live模型未验证时，不宣布可直接上生产。

## H. 开发版单与伙伴查阅（2026-09-25 补充）

**H01｜部分参考与可修改**
选择来源版单的支数但不选择成分/组织，只把支数带入；允许将来源 2/48 手改为 2/32，固定来源原值和本次值都可查。只作说明的图片不能自动改字段。来源更新不覆盖已采用的目标资料。

**H02｜版次与工厂轮次分开**
V1 给 A/B 两厂分别第一次打样，A 换纱后形成 V2，B 仍看 V1。重打相同要求只增加该厂轮次，其他厂记录不动。历史图片、字段和父版差异保留；历史没有留档的数据不得伪造。

**H03｜负责人发厂与接手**
谁负责谁发，无额外经理/业务员审批层。别人即使是经理也不能直接代发；需有留痕的负责人交接。负责人先核对固定工厂包，服务端再校验后系统内发厂；工厂仅可确认自己已收到的指定包，不见他厂报价、内部评价或未经授权图片。发厂、收到、审版、投产分别记录。

**H04｜建议到真实草稿**
问衣据查真实目标与固定来源 → 部分引用建议 → 人工修改/确认 → 服务端核对目标、依据、权限及上下文 → 写入实际草稿和审计 → 回到实际版单。规则/目标/内容变化后旧确认不能用，重复提交不重复执行。不采购、不批准资料、不自动发外部消息。

**H05｜单字候选与访问范围**
输入一个汉字、材料成分或 DEV 编号片段，出现按类别分组的可选候选，可打开原记录；更多结果可分页。中文组词期间不查，过期响应不覆盖新查询。工厂看不到他厂业务或组织外记录，失效账号不得搜索。

**H06｜伙伴查阅与真实流程**
客户按真实订单分当前/草稿/历史，品牌仅取订单款式关联；工厂看自己分配的订单、登记数量、阻塞和打样；供应商按明确供料凭证关联订单并保留退供/冲销。部分出运不得归为整单完成；不推算未登记工序，不将草稿叫预约产能，不从同料报价猜供应商采购。智能体与页面共用同一只读服务，已有凭证权限继续有效。

**H07｜款式库带入版单（2026-09-25）**
版单直接点“参考已有款”打开带图款式库，不要求先填版单类型。输入单字或部分款号/DEV编号可找候选；取消窗口不改版单。选择已有开发版次、当前开发草稿，或款式已批准资料中的明确材料。多种面料/纱线须选定，不猜大身用料。核对当前值/来源值后只带入勾选参数，取消勾选和来源缺项均保持原值；继续手改、保存，能回查来源原值和本次值。

保存时重新校验当前操作者、公司、目标更新时间、规则与来源指纹。首次采用后固定来源参数及选定图片，来源后续更新/换图不覆盖已存参考；不修改原款，不给原款新增版次。草稿来源明确标注未留档，款式批准状态不沿用。保存审计包含操作者、时间、前后内容与来源。保留原上传参考图和已留档版单的智能体提案流程；智能体暂不自动生成当前草稿/款式主档来源的采用提案，应引导到手动入口。

### 跟单元素与唛标规范（2026-09-27）

- 销售样固定图文项后可添加元素：名称、说明、最多六张图片；保存后可回查、检索，修改和移除进入操作者/时间/前后值审计。
- 大货同款同 PO 的主唛只填一次，总表跨颜色共用一格，打印只列一次。其他 PO 和原每色主唛历史不覆盖；旧差异或缺项须人工核对。
- 洗唛、尺码唛分开；黑白快选、自定义颜色经保存可再次选用。说明唛、备扣空白唛只有明确选择“同洗唛”才随本色洗唛颜色显示更新，独立选色不变。
- 贴布/毛毡、绣花/印花和套结合并为“特殊工艺”，其他辅料独立。旧工艺合并展示带原字段名称；手动清空新说明不会从旧字段反弹。旧洗尺唛说明不猜拆，编辑页、总表、打印、智能体仍可查原文。
- 保存继续使用跟单服务的权限、并发校验、幂等与审计，不自动采购、收料、批准或改其他批次。平台上下文 1.6.1，查询工具同步读取新字段。

- 大货共用主唛、纽扣/拉链/裤钩/其他辅料，以及每色金属标、洗唛/尺码唛/说明唛/备扣空白唛/吊牌/特殊工艺/其他辅料均可逐项添加图片（每项最多六张，JPG/PNG、单张不超过5MB）。保存并刷新后回查，总表可看图，打印按字段和适用颜色紧凑归组；不截断文字、不把图片塞成整页高的颜色行。
- 图片上传时不能保存未完成的跟单或切换款式；上传失败可重试，移除图片引用须保存后生效并保留前后审计。不同 PO、不同颜色互不覆盖；选择同洗唛不自动复制图片。工厂只读自身已关联记录的图片；图片张数不代表智能体已识别内容。
