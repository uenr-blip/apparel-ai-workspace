# 财务导航与办事首页

2026-09-20。财务入口仍为 /finance，现按五个工作区域组织，不再把十一项功能平铺成两行。

| 工作区域 | 从哪里开始 | 相关功能 |
| --- | --- | --- |
| 财务工作台 | 核对一笔款、登记与核对收付、查看订单成本 | 真实待办、最近到期款项、分币种未结金额、会计待处理 |
| 业务对账 | 客户款项 / 供应商和工厂款项 | 相关位置可进入订单单证、加工核对、材料凭证和收料退补 |
| 收付与结汇 | 收付款记录 / 退款登记 / 结汇换汇 | 延用现有登记、核销、退款和换汇流程 |
| 会计账务 | 业务入账 / 会计账簿 | 凭证、试算与科目明细；科目和期间收进账簿内的会计设置 |
| 订单成本 | 选择订单 | 材料、加工、其他费用与缺价/未归单提示 |

## 给第一次使用的人

- 要核对客户还差多少：财务工作台 → 客户款项 → 找客户或订单 → 核对金额与原始依据 → 关联实际到账。
- 要核对供应商或工厂该结多少：供应商 / 工厂款项 → 查看来源，应付需要的收料或加工依据在页面指引中可直接进入。
- 银行已经到账或已经付款：收付与结汇 → 收付款记录 → 登记已发生记录 → 找对应款项并分配。这里不发起真实银行交易。
- 要看订单花了多少钱：订单成本 → 选择订单 → 查成本构成和明细来源。
- 需要会计记账：会计账务 → 业务入账或会计账簿。建立账簿、科目和期间都在会计区，不妨碍先使用业务对账与收付登记。

每个工作页面都有简短操作顺序。「使用帮助」集中解释应收/应付、核销、未分配金额、会计账簿等用语，并保留正式启用范围说明。

## 保留的行为

原有 /finance?tab=receivables、payables、cash、documents、costs、treasury、ledger、bridge、reconciliation、vouchers 均保留，已有订单、账簿、状态和搜索条件继续传入原业务组件。原应收入口默认的订单结算视图也保留；新业务对账入口默认按款项查找。

「记账衔接」在新导航中称为「业务入账」，原地址不变。单证、加工与材料依据采用上下文入口，没有删除原功能。经理仍按原方式下发权限；导航变化不扩展任何动作授权。

只有会计查阅权限的账号看到财务工作台和会计账务，不读取客户/供应商业务余额；只读业务账号可查阅现有记录，看不到登记按钮。旧URL不能绕过缺失权限。

桌面使用五区导航，手机使用原生工作区下拉；子功能只显示当前工作区相关项。390宽度下可完成切换，宽表仍在卡片内滚动。

## 数据与验收边界

首页使用当前已登记业务：待确认单据、未分配流水、缺原件单证、加工待核对、按原币分别汇总的未结金额。没有数据不画假图；没有会计账簿不阻断业务首页。会计待处理总数按全部本组织账簿计算，首页只展示前六个账簿，不用截断样本作总数。

本轮不改变记账或资金算法，不新增schema，不创建正式账簿，不向原演示库导入验收记录。菜单整理不等于全面金额对账或正式财务规则已经完成。上线条件见 [OPS_READINESS.md](OPS_READINESS.md)。
